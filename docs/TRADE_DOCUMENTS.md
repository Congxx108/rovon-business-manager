# 可选外贸单据模块

更新日期：2026-10-08。

## 业务规则

客户要求时才制作 PI、Commercial Invoice（CI）或装箱单。每笔订单都可以没有这些单据，PI 可以不成单，CI 和装箱单可以直接制作。单据可关联已有订单，也可以独立存在；关联只用于查找。

保存、出具、复制、修订和作废只处理单据，不创建订单，不修改订单金额、付款、发货状态，不刷新客户统计，不改变 Dashboard 或每日潜客。已有订单只提供客户名、联系方式、品类和数量供核对；英文品名、成交币种/单价、实际箱规需按本次业务填写。

## 使用方法

1. 左侧进入“外贸单据”，选择新建 PI、CI 或装箱单。也可从订单列表/编辑页的单据入口进入；订单关联是可选项。
2. 编号留空会自动生成，也支持手动编号；同类型编号不可重复。填写买卖方与商品资料，图片支持 PNG/JPEG，浏览器会压缩。
3. PI/CI 选择成交币种和银行配置。原 PI、CI 的账户差异分别保留；本单账户资料可编辑或完整手动覆盖。单据币种与订单人民币统计独立，不自动换算。
4. 装箱单建立实际装箱组，填写箱数、单箱毛重/净重 kg、外箱长宽高 cm。混箱商品选择同一组，箱数、重量和体积只计一次，商品数量分别相加。不同箱规建立不同组。
5. 保存草稿后预览/下载 PDF；点击“确认出具 PDF”保存正式版本。正式版本固定存储，修改单据后保存修订草稿，再次出具新增版本。历史版本可继续下载。
6. 可复制为 PI、CI 或装箱单，生成独立新编号并保留来源关系。作废保留 PDF 历史，需重新使用时复制为新单。
7. 公司、银行、常用条款设置只影响后续新单据；已有单据保存自己的资料副本。多窗口同时修改时，旧版本保存会明确提示冲突。

## PDF 模板边界

- 原 XLSX 未修改，固定版式来自清除客户、商品、价格和账户资料后的 WPS 矢量底版。
- PI 纵向每页四条、CI 纵向每页两条、装箱单横向每页五条；多页重复表头，最后正文页显示整单总计，混箱不重复累计。
- 过长地址、条款、银行信息、描述等以“See details”指向附页，附页保留完整内容；不会悄悄截掉数据或为了塞入而无限缩小字体。
- 固定 Logo、标题、色块、边框直接复用原表；动态英文和中文字体与 WPS 原字体可能有细微差异。中文使用完整嵌入，含中文的 PDF 约增加 6 MB，文件由私有存储直接提供。
- 单价最多四位小数，逐行金额四舍五入到两位再汇总；费用两位，重量三位，CBM 为箱数 × 长 × 宽 × 高 ÷ 1,000,000 并保留三位。

## 数据与权限

- `trade_documents`：类型、编号、日期、可选订单/来源、草稿状态、修订号及完整资料快照。
- `trade_document_versions`：每次出具的快照、PDF 路径和 SHA-256，应用服务无更新/删除权限。
- `trade_document_settings`：新单默认公司、币种、PI/CI 银行配置和条款；版本号防止覆盖其他窗口的修改。
- 私有桶 `trade-document-files`：不可变商品图片、草稿预览、正式版本 PDF；登录后服务器签发五分钟链接。
- 页面和 API 检查 Supabase Auth；修改 API 检查同源。三张表启用 RLS，匿名/普通登录角色没有直读权限，由已认证服务端使用 service role 读写。RLS 无直接访问策略属于此架构的预期设置。
- PDF 上传成功后，数据库在锁定修订号的事务中保存版本；冲突只清理本次未被采用的 PDF。旧 PDF 不随设置或资料改变而重新生成。

迁移文件：`supabase/migrations/20261008033128_optional_trade_documents.sql`。生产迁移已执行，账号另行私有初始化；新环境先迁移，再通过受保护设置页填写公司/账户。Vercel 部署不会自动运行 Supabase migration。

模板资源见 `assets/trade-documents/README.md`。修改模板需重新清除动态样本资料，校准 PDF 网格并渲染比对，不能将带真实客户/账号的 XLSX 或参考 PDF 提交。Next.js 文件追踪显式包含模板和字体，以保证部署环境可以生成 PDF。
